# webmail

Почтовый веб-клиент на Go: один бинарь со встроенным SPA (Vue 3), работает с любым
IMAP + SMTP submission (+ ManageSieve) сервером по своему конфигу. Интерфейс — в духе
десктопных клиентов: папки, список писем, панель чтения и карточка собеседника.

Лицензия — MIT. Интеграции с панелями хостинга подключаются как адаптеры через
публичный пакет `ext` и в ядро не входят.

## Установка

```sh
make web build                 # SPA + бинарь bin/webmail
sudo make install              # systemd-сервис webmail (deploy/install.sh)
sudo nano /etc/webmail/config.yaml && sudo systemctl restart webmail
journalctl -u webmail -f
```

`deploy/install.sh` создаёт пользователя `webmail`, `/etc/webmail/` с конфигом из примера
и секретом сессии, ставит юнит с песочницей (`systemd-analyze security webmail` — 1.4)
и запускает сервис, только если `webmail config check` проходит. Повторный запуск
обновляет бинарь и юнит, не трогая конфиг и секрет. Переменные `WEBMAIL_*` можно
положить в `/etc/webmail/webmail.env`.

Без systemd:

```sh
./bin/webmail gen-secret > session.key && chmod 600 session.key
./bin/webmail config check -config config.yaml
./bin/webmail serve -config config.yaml
```

Минимальный конфиг для обычного Postfix + Dovecot (полный пример — `deploy/config.example.yaml`):

```yaml
version: 1
server:
  public_url: https://mail.example.com
session:
  secret_file: /etc/webmail/session.key
imap:
  host: mail.example.com
  port: 993
  security: tls
smtp:
  host: mail.example.com
  port: 587
  security: starttls
```

Сервер слушает `127.0.0.1:8080`; TLS обычно завершает nginx или caddy перед ним
(адрес прокси должен быть в `server.trusted_proxies`, по умолчанию 127.0.0.1).

### Несколько адресов и путь под прокси

Один экземпляр можно опубликовать сразу под несколькими адресами и под путём:

- `server.multi_host: true` — изменяющие запросы принимаются не только с
  `public_url`, но и с того адреса, по которому открыт сам запрос (заголовок `Host`
  и `X-Forwarded-Proto` от доверенного прокси). Так работает `webmail.<домен>`
  для каждого домена сервера.
- `X-Forwarded-Prefix` от доверенного прокси — путь, под которым опубликован webmail
  (например, `/webmail`). Прокси отрезает его сам, а webmail ставит `<base href>`,
  путь cookie и ссылки от этого пути:

```nginx
location ^~ /webmail/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Prefix /webmail;
}
```

### Правила конфига

- Неизвестный ключ — ошибка при старте.
- Любой ключ переопределяется переменной окружения: `WEBMAIL_IMAP__HOST`,
  `WEBMAIL_SESSION__IDLE_TIMEOUT=45m`, списки — через запятую. Переменные
  без `__` (кроме `WEBMAIL_CONFIG`) к конфигу не относятся и игнорируются.
- Секреты — только файлами `*_file` с правами 0600; в YAML их нет.
- `webmail config show` печатает итоговый конфиг со значениями по умолчанию.
- `security: none` разрешён только для loopback-адресов.

Полный список ключей — `internal/config/config.go` (`Defaults`).

### Брендинг

Название, логотип и цвета задаются секцией `ui.brand`:

```yaml
ui:
  brand:
    name: Почта Ромашки
    logo_file: /etc/webmail/brand/logo.svg       # или logo_url: https://…
    logo_dark_file: /etc/webmail/brand/logo-dark.svg
    favicon_file: /etc/webmail/brand/favicon.png
    accent: "#0b7a5c"                            # accent_dark — для тёмной темы
```

Файлы (svg/png/jpg/webp/gif/ico, до 1 МиБ) читаются при старте и раздаются по
`/brand/logo`, `/brand/logo-dark`, `/brand/favicon` с долгим кешем; после замены
файла нужен перезапуск. Из `accent` интерфейс сам считает фон выделения и цвет
текста на кнопках для светлой и тёмной темы; `css_vars` переопределяет любые
переменные из `web/src/styles.css`. Адаптер может отдавать бренд по хосту через
`ext.BrandProvider` — его непустые поля перекрывают конфиг. `hide_about: true` убирает
кнопку и окно «О программе» (провайдер тоже может его скрыть).

### Язык и тема

Интерфейс переведён на английский и русский; язык выбирают на экране входа или в
настройках («Внешний вид»), выбор хранится в браузере. Пока пользователь не выбрал
сам, действует `ui.default_language` (по умолчанию `en`); `ui.languages` ограничивает
список (по умолчанию предлагаются все языки).

Другие языки подключаются языковыми пакетами без пересборки: файл `<код>.json` в
каталоге `ui.locales_dir` (например, `uz.json`), webmail читает их при запуске.
В пакете — название языка, локаль дат, строки интерфейса (ключи `web/src/locales/en.ts`)
и тексты сервера (ключи `Server["en"]` в `internal/locale/locale.go`):

```json
{
  "name": "O'zbekcha",
  "date_locale": "uz-Latn-UZ",
  "ui": { "login.title": "Pochtaga kirish" },
  "server": { "sieve.vacation": "Avtojavob" }
}
```

Непереведённые строки показываются по-английски; битый пакет пропускается с
предупреждением в журнале. Словарь пакета клиент загружает при выборе языка
(`GET /api/v1/locales/{код}`), список языков с названиями приходит в `/api/v1/config`. Тема по умолчанию — `ui.theme` (`light`, `dark`, `system`); переключатель —
на экране входа и на левой панели. Строки интерфейса — в `web/src/locales/`: `en.ts`
эталонный, остальные словари проверяются по нему при сборке.

Тексты, которые пишет сервер, идут на языке интерфейса пользователя: уведомления о
прочтении, ответы на приглашения, имена правил «Автоответ»/«Пересылка» в Sieve.
Клиент передаёт язык в cookie `wm_lang`; если её нет, сервер берёт язык из
`Accept-Language`, затем `ui.default_language`.

Язык и тему можно задать ссылкой: `/?lang=ru&theme=dark` (выбор запоминается в браузере).
Панель хостинга передаёт их в токене SSO, см. [docs/integration.md](docs/integration.md).

Данные пользователей (отправители, подписи, контакты) лежат в SQLite: под systemd —
`/var/lib/webmail/webmail.db`, иначе — `./webmail.db` (или путь из `storage.dsn_file`).
Фильтры включаются секцией `sieve: {enabled: true}`; хост по умолчанию — `imap.host`.
Смена пароля — секция `password` и драйвер, см. [docs/password.md](docs/password.md).
Вход из панели хостинга и служебный API — [docs/integration.md](docs/integration.md).

## Что уже работает

| Область | Состояние |
| --- | --- |
| Вход | Логин/пароль через IMAP, домен по умолчанию, лимиты попыток по IP и ящику |
| Сессии | Своя cookie; пароль IMAP хранится зашифрованным, ключ — частично только в cookie |
| Папки | SPECIAL-USE + имена как у Roundcube, счётчики через LIST-STATUS, вложенность; создание, переименование и перенос (с подпапками и подписками), удаление, подписка («Настройки → Папки»), «отметить все прочитанными», очистка Корзины и Спама; выгрузка папки в mbox (mboxrd, флаги в Status/X-Status) и загрузка писем из .mbox и .eml с исходными датами и флагами, без дублей по Message-ID; спецпапки защищены от переименования и удаления |
| Список | Сортировка на сервере (SORT), поиск, фильтры, группировка по датам, мультивыбор, drag & drop в папки; цепочки писем (IMAP THREAD REFERENCES, переключатель «Цепочки»): строка цепочки — самое новое письмо со счётчиком писем и непрочитанных, разворачивается деревом; удаление, перенос и архив свёрнутой цепочки — всеми её письмами |
| Чтение | Санитизация HTML (bluemonday + свои правила), блокировка внешних картинок, cid-картинки, вложения, все вложения одним ZIP (имена очищены от путей), исходник .eml, печать; важность в списке и письме; ответ на запрос уведомления о прочтении (RFC 8098: спрашивать / отправлять, если адрес совпадает с отправителем / никогда; $MDNSent) |
| Приглашения | Письма с iCalendar (text/calendar или вложение .ics, iTIP RFC 5546): карточка встречи над текстом — дата и время в местном поясе (TZID из tzdata, а для имён Outlook вроде «Russian Standard Time» — из VTIMEZONE письма с переходами на летнее время), место и ссылка, организатор, участники с ответами; отмена (CANCEL), ответы участников (REPLY), изменение встречи, повторения. «Принять / Под вопросом / Отклонить» с комментарием отправляют организатору METHOD:REPLY от адреса ящика или отправителя, который есть среди участников; копия — в «Отправленные», письмо помечается `\Answered` и `$RSVPAccepted` / `$RSVPTentative` / `$RSVPDeclined`, ответ можно изменить. С включённым календарём принятая встреча сохраняется в него (повторное письмо обновляет её по UID), отклонённая или отменённая — убирается; кнопка «В календарь» есть и у писем без ответа (PUBLISH) |
| Отправка | Новое, ответ, ответ всем, пересылка, вложения, копия в «Отправленные», флаги \Answered / $Forwarded; важность (X-Priority + Importance), запрос уведомления о прочтении (MDN) и о доставке (SMTP DSN) |
| Редактор | TipTap: форматирование, списки, ссылки, отмена; картинки в тексте (вставка, перетаскивание, кнопка; крупные уменьшаются до 2000 px) уходят частями multipart/related с cid, в том числе из цитаты и продолжаемого черновика; шаблоны ответов («Настройки → Шаблоны ответов», вставка и «Сохранить текст как шаблон» в окне письма); цитата исходного письма хранится отдельно и уходит без изменений вёрстки; файлы, брошенные или вставленные в текст, становятся вложениями |
| Орфография | `spellcheck.engine`: `browser` (по умолчанию) — проверка браузера; `hunspell` — на сервере (`apt install hunspell hunspell-ru hunspell-en-us`): волнистое подчёркивание, варианты по правому клику, «Добавить в словарь» (личный словарь ящика, «Настройки → Орфография»), выбор словаря или всех сразу для смешанного текста; `off` — выключена |
| Черновики | Автосохранение через 4 с после правки, сохранение при закрытии окна, продолжение из папки, перенос вложений, Bcc сохраняется |
| Отправители | Несколько отправителей с именами, Reply-To, скрытой копией и HTML-подписью; выбор в окне письма; адрес ограничен `identities.level` (single/domain/any) |
| Фильтры | ManageSieve: правила формой (условия по полям, заголовкам, тексту, размеру; переместить, копировать, переслать, отклонить, пометить, удалить), автоответ с датами, пересылка; формат правил Roundcube (`# rule:[…]`), правится активный скрипт; что нельзя показать формой — открывается как текст; защита от перезаписи чужих правок |
| Пароль | «Настройки → Пароль»: политика (длина, группы символов, имя ящика, утечки HIBP), проверка текущего, сброс других сессий; драйверы `exec` (в т. ч. встроенный помощник для Dovecot passwd-file) и `http`; сразу после входа из панели (`password.sso_window`) — без текущего пароля — см. [docs/password.md](docs/password.md) |
| Панель хостинга | Адаптер `adapters/panel`: вход в почту из панели по одноразовой ссылке, подписанной HMAC (срок до 2 минут, повтор не пускает, ограничение по доменам), — ядро входит в IMAP, SMTP и ManageSieve мастер-учёткой Dovecot, пароль ящика панели не нужен; служебный API с токеном и списком адресов — завершить сессии ящика и удалить его данные. Формат токена, примеры на PHP и shell, настройка Dovecot — [docs/integration.md](docs/integration.md) |
| Контакты | Адресная книга с группами, поиск по имени, адресу, телефону; «собранные адреса» — получатели отправленных писем; подсказки в полях адреса (группа раскрывается в участников); импорт и экспорт vCard и CSV (Outlook, Gmail, Thunderbird, в т.ч. Windows-1251); «В контакты» из карточки собеседника |
| Внешние книги | Адаптер `adapters/carddav` (открытый, вне ядра, включается `adapters.carddav`): пользователь подключает свой CardDAV-сервер (Nextcloud, SOGo, Radicale, Baïkal, iCloud) — поиск книг по адресу сервера, принципала или книги, пароль хранится зашифрованным ключом сервера; администратор задаёт пресеты для всех ящиков (`%u`/`%l`/`%d`, пароль ящика из сессии — не хранится). Карточки кэшируются в БД (подсказки адресов, поиск), синхронизация по ETag раз в 15 минут и по кнопке; правка и удаление идут на сервер с If-Match, поля вне формы (фото, адреса, дни рождения) сохраняются; книги только для чтения; группы — локальные; пользовательские учётки не ходят во внутренние сети (`allow_private_networks`) |
| Календарь | Адаптер `adapters/caldav` (включается `adapters.caldav`): календари из пресетов администратора на CalDAV-сервере (Radicale, Nextcloud, SOGo, Baïkal), те же `%u`/`%l`/`%d` и пароль ящика из сессии, что у книг. Ядро ничего не хранит: события за показанный диапазон запрашиваются у сервера (`calendar-query` с `time-range`), повторения (RRULE, RDATE, EXDATE, исключения с RECURRENCE-ID) разворачиваются на сервере webmail с учётом поясов и летнего времени. Виды «Месяц», «Неделя», «Список»; создание, правка (у серии — вся серия), удаление события, одного повторения или серии; поля вне формы (напоминания) сохраняются; конфликт правок — по ETag. Участники встречи: адреса с подсказками из контактов, организатор — ящик; при сохранении участникам уходит METHOD:REQUEST (приглашение или изменение, SEQUENCE растёт), убранным из встречи и при удалении — METHOD:CANCEL; ответы REPLY записываются в PARTSTAT встречи организатора при открытии письма. У чужой встречи (ящик — участник) состав не меняется и писем нет. Общие календари: пресет с `collection: true` смотрит прямо в набор календарей, `writers` говорит, кому можно писать, остальным — только чтение (замок в списке). Подробности и следующие этапы — [docs/calendar.md](docs/calendar.md) |
| Обновления | Новые письма во «Входящих» — push (IMAP IDLE → Server-Sent Events), остальные папки — опрос; непрочитанные в заголовке вкладки |
| Действия | Прочитано, флаг, перемещение, удаление в корзину / навсегда из корзины и спама; «В архив» — одной папкой или по годам / месяцам (`Архив/2025/03`, как archive_type в Roundcube), подпапки создаются сами |
| UI | Светлая и тёмная темы, бренд через CSS-переменные, адаптивная вёрстка, горячие клавиши |
| Безопасность | CSRF-токен + проверка Origin, CSP, письма в iframe без скриптов, аудит-лог |

Пока нет: группы CardDAV (KIND:group), хранилища сессий sqlite/redis.
План — в техническом задании.

За reverse proxy поток `/api/v1/events` должен проходить без буферизации
(для nginx сервер сам отдаёт `X-Accel-Buffering: no`; `proxy_read_timeout` — больше 25 с).

## Разработка

```sh
make devstand        # Postfix + Dovecot 2.4 на 127.0.0.1, ящики alice@/bob@test.local, пароль Test12345!,
                     # мастер-учётка и ключи адаптера panel в deploy/devstand/
make run             # сервер с deploy/devstand/config.yaml
cd web && npm run dev  # Vite с проксированием /api на :8080
make test            # go vet, юнит-тесты, проверка типов фронтенда
make test-it         # интеграционные тесты против стенда
make e2e             # сквозной сценарий в headless Chromium (нужен playwright-core и chromium)
```

## Устройство

```
cmd/webmail/       main ядра: app.Main()
app/               публично: Main/Run(cfg, adapters...) — точка входа и для сборок с адаптерами
ext/               публично: интерфейсы точек расширения (semver)
internal/config    загрузка и проверка конфига
internal/session   сессии BFF
internal/mail      IMAP (go-imap v2), SMTP, MIME
internal/sanitize  очистка HTML писем
internal/sieve     клиент ManageSieve, разбор и генерация Sieve
internal/store     SQLite: отправители, подписи, контакты, группы, собранные адреса
internal/contacts  импорт и экспорт vCard / CSV
internal/api       REST API для SPA и реализация ext.Core
internal/web       встроенный SPA
web/               исходники SPA (Vue 3 + TypeScript)
deploy/devstand    тестовый почтовый стенд
```

Адаптер живёт в своём модуле и собирает свой бинарь:

```go
package main

import (
	"github.com/ibuben/squareball/app"
	"example.com/panel/webmailadapter"
)

func main() { app.Main(webmailadapter.New()) }
```

Включается секцией `adapters.<name>: {enabled: true, ...}` в конфиге.
